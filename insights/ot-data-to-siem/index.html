Executive summary

Critical infrastructure is now a standing target. The question is no longer whether a network will be probed, but whether a probe can ever become a path.

In modern industrial and critical infrastructure environments, cyber threats are constant and evolving. Any system — directly or indirectly — can become a point of vulnerability. Power grids, substations, energy plants, dams and industrial control systems are increasingly targeted by ransomware, intrusion attempts and data exfiltration campaigns.

To address this, the unidirectional data diode provides a hardware-enforced, air-gapped solution that ensures secure, one-way data transfer between isolated networks — without exposing internal systems to any form of return communication or logical interaction.

Unlike firewalls or proxies that rely on configurable software, the diode operates through fixed, FPGA-driven logic. It allows only authorized protocols and file types while blocking all others at the hardware level — delivering deterministic, tamper-proof data flow with zero exposure.

“Data leaves. Nothing returns. The return path is not blocked by a rule that can be changed — it does not physically exist.”

Introduction

A SOC cannot defend what it cannot see. The difficulty is that visibility has always been sold as a two-way connection.

Security operations depends on telemetry — syslog from switches and servers, events from historians, alarms and state changes from the control layer. In IT this is routine plumbing. In OT it is a design problem, because the collector that reaches into the plant to gather those logs is, by construction, a device with a route into the plant.

Why OT monitoring lags

Limited monitoring and logging is one of the defining vulnerabilities of OT environments: many networks lack real-time visibility, which makes anomaly and intrusion detection difficult. That gap is rarely a matter of indifference. It persists because every conventional way of closing it introduces an inbound path that the plant’s own safety case cannot accept.

At the same time, IEC 62443 and NIST SP 800-82, along with national cyber regulation, expect evidence of monitoring, logging and event retention — including for systems that are deliberately isolated. The operator is asked to prove something about a network they have been told not to connect.

What the SOC actually needs out of OT

  • Syslog from network, security and server infrastructure inside the zone.
  • Process and historian events that give context to a security alert.
  • Alarm and state changes from the control layer, time-correlated with IT events.
  • Asset and firmware changes, so an unexpected update is visible as it happens.
  • A record auditors can trust not to have been edited by whoever triggered it.

Challenges

Every standard route from OT to the SIEM creates exactly the path an attacker wants.

  • Collectors live inside OT. A log forwarder or agent in the plant needs credentials, a patch cycle and an open channel to the SIEM. It is one more networked computer in the zone you were protecting.
  • Firewall rules drift. A narrow outbound allowance widens over time. A rule is a promise an administrator can change; nothing physically prevents the reverse direction.
  • Dual-homed gateways are bridges. A box with one interface in OT and one in IT removes the segmentation it was bought to preserve the moment it is compromised.
  • The SIEM becomes a pivot. It is reachable from everywhere by design and holds credentials for everything — a high-value target with routes back toward the plant.
  • Logs can be edited. Where the path is bidirectional, an intruder who reaches the collector can suppress or rewrite the record of the intrusion itself.
  • Polling breaks the model. Many monitoring protocols require the server to query the device. That query is an inbound session, however it is framed.

Why Terafence

Forward the telemetry. Leave no route behind it.

Terafence sits in-line between the OT segment and the monitoring network. Side A receives syslog, events and files from the plant. Side B independently re-publishes that stream to the SIEM, log collector or monitoring platform. Each side terminates its own TCP/IP session, so no session is ever established end to end.

The core is FPGA logic operating at OSI layers 1 and 2, with no IP or MAC address in the FPGA data-path core. There is nothing on the protected side for the SIEM — or for anything that has compromised the SIEM — to address, scan or reach.

Because the unit stores no raw data, telemetry is forwarded rather than retained. There is nothing to exfiltrate from the gateway itself, and no obligation to secure data at rest inside it.

What this changes

  • Native one-way forwarding. SYSLOG and local SYSLOG forwarding are carried natively; the SIEM receives an ordinary stream and needs no modification.
  • No agent exposure. Nothing inside OT has to accept an inbound connection from the monitoring network.
  • Tamper-resistant by construction. With no network path from the SIEM side back to the source, forwarded records cannot be altered at origin from the IT side.
  • Several streams at once. Syslog, file transfer and broker protocols run simultaneously within 1 Gbps of throughput.
  • Evidence for the reviewer. IEC 62443-4-2 assessment, EMC and FCC test documentation available on request.
